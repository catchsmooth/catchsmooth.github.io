## 先理解连接，再谈编排

MCP 是连接 AI 应用与外部工具、数据的协议。它本身不替你决定一项任务应该如何执行。先从官方介绍理解应用、客户端和服务器之间的关系，再阅读协议架构。

## 按这个顺序阅读

1. 从 MCP 官方概览开始，理解它连接了什么。
2. 查看 Playwright MCP 的仓库说明，以浏览器交互作为具体工具案例，阅读配置与能力边界。
3. 阅读 MCP Inspector，了解如何连接服务、检查工具与调试调用。
4. 当流程确实需要状态和编排时，再进入 LangGraph 官方概览。

## 如何选择下一步

已经有 AI 客户端，只想连接工具，先关注 MCP 连接方式。正在开发服务，关注 Inspector。需要控制多步骤任务的状态和流程，才进一步研究编排框架。

## 把边界也纳入设计

阅读工具文档时同时检查可访问的数据、可执行的操作与确认机制。本站提供的是学习路径与官方入口，不运行 MCP 服务，也不代替具体项目的集成验证。
